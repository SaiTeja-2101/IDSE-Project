# Beginner playtest guide

Ask three to five classmates with little or no coding experience to play. Ask if you can keep anonymous notes on what they learned. Use labels like P1 and P2. Put the results in the [playtest evidence log](PLAYTEST_EVIDENCE.md).

## Run a session

1. Before showing the game, ask: "If an AI is trained on past hiring decisions, what might it get wrong?" Record the response as given.
2. Ask them to play without an explanation. Only help if they are blocked. Record where, for example opening the first CV, finding the complaint, or reading the practice table.
3. When the receipt appears, ask: "What was a detail Scout read? What answer did it learn from?" Use their own example if they have one.
4. Ask: "What did you change on the test copy? What happened? Does that tell you how every applicant would be treated?"
5. Ask: "What did your repair change? How did you check whether it helped? Why use new CVs for the final check?"
6. Try a transfer question: "A recycling model sees most glass photos on blue backgrounds. How could you test if it uses the colour?" Ask what one part of the game they would change.

After the sessions, count how many people could explain each idea without help. Note one thing that confused a player, what you changed, and whether it helped when someone tried it again. Keep automated checks and your own demo separate from peer feedback.

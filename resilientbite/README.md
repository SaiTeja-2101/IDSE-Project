# ResilientBite

ResilientBite forecasts portions required for each scheduled menu item, meal and dining hall. It tests whether a daily forecast improves on using the same day last week and compares three preparation rules on excess and unmet portions.

**Quick review:** [report](../submission/ResilientBite-Report.pdf), [presentation](../submission/ResilientBite-Presentation.pptx), [notebook](food_pred%20%281%29.ipynb), [code and evidence map](../REVIEW.md#part-a-resilientbite).

## Reproduce

Use Python 3.13.9, the version used to verify the notebook. Run these commands from the folder containing the notebook and CSV.

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyter lab
```

Open `food_pred (1).ipynb`, select the Python kernel from this environment, and choose **Restart Kernel and Run All Cells**. The notebook generates the practice CSV and exports five results tables beside it. To run from the command line and save refreshed outputs in the notebook, use this command from the same activated environment.

```sh
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=300 'food_pred (1).ipynb'
```

The raw CSV is read-only during execution. The forest uses seed 42. Each forecast uses weekend, vacation and exam flags plus demand from yesterday and the same day last week.

## Daily forecast app

From the project folder, use the same Python environment to install and start the local app.

```sh
python -m pip install -r forecast_app/requirements.txt
python -m streamlit run forecast_app/app.py --server.address 127.0.0.1
```

Open the Local URL printed by Streamlit. The home screen shows the required columns and asks for a CSV or Excel `.xlsx` file. A valid upload automatically generates today's forecast. Use the same upload control to replace the file. While the app is open, the forecast checks the computer's date every minute. With no file selected, **Historical demo** replays a day from the 2024 project dataset.

Use the original CSV headers or this smaller set of columns:

| Column | What to enter |
| --- | --- |
| `date` | Date in YYYY-MM-DD format or an Excel date cell |
| `dining_hall`, `meal`, `food_item_id` | The same combination for a dish across all three dates |
| `food_item_name` | Dish name to display |
| `actual_demand_portions` | Whole portions for yesterday and seven days ago. Leave today's value blank. |
| `is_vacation`, `is_exam_period` | Optional 0 or 1 for today's schedule. The app offers defaults. |

For today's forecast, include one menu row per dish, meal and hall plus the corresponding historical demand rows. If today's menu is absent, the app labels last week's menu as an estimate. A dish needs both historical values before it can receive a portion forecast. The supplied CSV ends in 2024, so use Historical demo with that file.

The backend rebuilds the notebook's selected Random Forest from its original training period and caches it locally. Uploaded files supply the menu and recent demand. The app lists the scheduled or estimated dishes and forecasts their portion counts.
